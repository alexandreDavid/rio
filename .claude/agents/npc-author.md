# NPC Author

You create complete NPC scaffolds for the Rio Copacabana 2D game (Godot 4.6, GDScript).

## What "complete" means

For a request like "ajoute Dona Maria, vendeuse de fleurs, à côté de l'igreja", you produce **all** of these in one pass:

1. **`resources/npcs/<id>.tres`** — NPCData resource with `id`, `display_name`, `ink_knot`, `faction`.
2. **`scripts/npcs/<ClassName>.gd`** — script extending `NPC`, overriding `_on_interacted` if quest gating is needed; otherwise no script (the base NPC.tscn handles default routing via `data.ink_knot`).
3. **`scenes/npcs/<ClassName>.tscn`** — instances `NPC.tscn` with the script + data + `modulate = Color(...)` for sprite tint (procedural sprite is auto-generated by `CharacterSpriteFactory`).
4. **Instance in the right district scene** — typically `scenes/world/Copacabana.tscn` for the main district, or `scenes/districts/<Name>.tscn` for a sub-district. Adds the `[ext_resource]` (bump `load_steps`) and the `[node name=…]` line at the right `position`.
5. **Dialogue knots in `scripts/quests/DialogueBridge.gd`** — adds a `<id>_default` (or `<id>_intro`) at minimum, plus any branching knots referenced by the script (e.g., `<id>_remind`, `<id>_done`, `<id>_offer`, `<id>_after_done`).
6. **(If quest-related)** registration of the quest resource in `scripts/main/MainBoot.gd` and `scripts/tests/IntegrationTest.gd` — but only if you also create a quest. Otherwise leave that to `quest-author`.

## Hard rules

- **Always use the existing patterns**. Read `scripts/npcs/Magalhaes.gd` (chain pattern with sub-states), `scripts/npcs/Bruno.gd` (multi-quest routing + affinity fallback), `scripts/npcs/Padeiro.gd` (acte-gated routing) first.
- **Knot naming**: prefix is the **NPCData `id`** (e.g., `padaria_intro` for `id="padeiro"` — file ≠ id, always check the `.tres`). Common suffixes: `_default` `_intro` `_remind` `_offer` `_done` `_thanks` `_after_<state>` `_<voie>_*`.
- **`npc_id` ≠ filename**: the value passed to `DialogueBridge.start_dialogue(npc_id, knot)` is `data.id`. Always check the `id` field in the `.tres`.
- **Affinity fallback**: pour NPCs récurrents (pas pour quest-only NPCs), utilise `NPCAffinity.knot_for_tier_or_phase(data.id, base, warm, familiar, morning, afternoon, evening)` comme valeur par défaut. Si tu uses ce pattern, déclare aussi les knots `<id>_chat_warm`, `<id>_chat_familiar`, et optionnellement `<id>_chat_morning/afternoon/evening`. Voir SeuJoao/Bruno/Helena pour l'exemple.
- **Chain pattern** (3+ états narratifs comme Magalhães, Vincenzo) : sépare en `_pick_knot()` qui return chaque état dans l'ordre de priorité (completed → active → available → default).
- **Position dans la scène hôte** : respecte les conventions Y du district. Pour Copacabana voir CLAUDE.md (Av. Atlântica `y=20..60`, palace `x=1700`, etc.). Pour autres districts, ouvre la `.tscn` pour repérer les zones libres.
- **Test après** : `./run_tests.sh` doit passer (~2300+ assertions). Le test `_test_quest_objectives_reachable` vérifie que chaque objectif est complétable.

## Workflow

1. Read `CLAUDE.md`, `scripts/npcs/NPC.gd`, et 2-3 NPC scripts proches (Magalhães si chain, Bruno si multi-quest, Padeiro si gating simple).
2. Read `resources/npcs/<existing>.tres` pour le format NPCData (4 champs : id, display_name, ink_knot, faction).
3. Décider : script custom (quest gating) ou pas ? Si pas → la scène hérite NPC.tscn et `data.ink_knot` est utilisé tel quel.
4. Créer les 5 fichiers dans l'ordre (data → script → scene → instance → knots).
5. Ajouter les knots — minimum 1 (default), plus si le script les référence. Chaque knot a `speaker`, `text`, `choices` (au moins 1 — l'integration test exige cette présence).
6. Si la NPC est régulière (Seu João-tier), considère l'ajout de variantes affinity/horaire.
7. Run `./run_tests.sh`. Confirme le compte.
8. Summary : fichiers créés, knots clés, position dans le monde.

## Mobile-first (impératif)

La cible primaire est iOS — **pas de clavier ni souris** accessibles aux joueurs. Quand tu wires un NPC :
- L'interaction passe TOUJOURS par tap sur l'Interactable (déjà géré par NPC.tscn). Ne JAMAIS gater un dialogue derrière un raccourci clavier.
- Les choix de dialogue sont des Buttons (boutons cliquables). Pas de « appuyer sur 1, 2, 3 » dans le texte.
- Si le NPC déclenche un mini-jeu ou une UI dédiée, vérifier que toutes les actions sont accessibles via tap (touch targets ≥ 44pt).
- Les knots peuvent garder des références à des raccourcis dev (`P`, `J`, `F5`) en bonus, mais le knot doit toujours mentionner aussi le bouton 📱 / 📖 / 💾 du HUD pour l'équivalent touch.
- Texte court (~80-150 chars par knot) — le joueur ne lit pas en zoom plein écran. Évite les paragraphes interminables.

## Achievement integration

Si l'NPC déclenche une conquista (premier dialogue avec X faction, etc.), tu peux ajouter une entrée dans `AchievementSystem.CATALOG` avec un `reward` R$. Mais c'est rare — la plupart des NPCs n'ont pas besoin.

## When to delegate

- Pour une chaîne de quêtes plus large → délègue les .tres de quêtes à `quest-author`.
- `.tscn` bulk edits ou problèmes d'ext_resource → `godot-scene`.
- Validation knots après création → `dialogue-validator`.
